# Frontend Development Guidelines

This file guides frontend development across all payment integrations in MyWebAPI.

## Directory & File Organization

**Rule: Keep HTML/JS/CSS pairs together** in integration-specific folders:

```
wwwroot/
├── {IntegrationName}/          ← Folder per major integration
│   ├── {name}.html             ← UI form
│   ├── {name}.js               ← Client-side logic
│   └── {name}.css              ← Optional styling
├── test/                       ← Shared test utilities
│   ├── devFillers.js           ← Form auto-fill functions
│   ├── factories/              ← Data generation
│   └── api.js                  ← API helpers
└── utilities.js                ← Shared nav bar
```

New integrations: Create a folder matching the backend controller name (e.g., `YourIntegration/yourintegration.html`).

## API Communication Patterns

### Making API Calls

```javascript
// POST to backend controller
async function processPayment(paymentData) {
  try {
    const response = await fetch("/api/yourintegration", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(paymentData),
    });

    if (!response.ok) {
      const error = await response.text();
      throw new Error(`API Error: ${response.status} - ${error}`);
    }

    const result = await response.json();
    console.log("Payment processed:", result);
    return result;
  } catch (error) {
    console.error("Payment failed:", error);
    throw error;
  }
}
```

### Collecting Form Data

```javascript
function getFormData() {
  const elements = document.querySelectorAll("form input, form select");
  const formData = {};

  elements.forEach((el) => {
    if (el.name) {
      formData[el.name] = el.value;
    }
  });

  return formData;
}
```

## 3D Secure Integration

### Token & 3DS Data Handling

When 3DS is required, pass these fields from frontend to backend:

```javascript
const paymentRequest = {
  paymentToken: tokenFromNmiWidget,
  amount: parseFloat(amount),
  
  // 3DS fields (when applicable)
  cardHolderAuth: "verified", // "verified" or "attempted"
  cavv: cavvFromThreeDSecure,
  eci: eciFromThreeDSecure,
  xid: xidFromThreeDSecure,
  directoryServerId: dsId,
  threeDsVersion: "2.1.0",
};
```

### NMI Payment Component (3DS Example)

```javascript
import { mountNmiThreeDSecure } from "@nmipayments/nmi-pay";

// Initialize 3DS
const threeDSInstance = mountNmiThreeDSecure(containerElement, {
  clientSessionId: sessionId,
  onAuthentication: (authData) => {
    console.log("3DS Challenge Result:", authData);
    // Send authData.cavv, authData.eci to backend
  },
```

## UI Feedback & User Experience

### Show Processing State

```javascript
function showProcessing(isProcessing) {
  const submitBtn = document.getElementById("submitBtn");
  submitBtn.disabled = isProcessing;
  submitBtn.textContent = isProcessing ? "Processing..." : "Pay Now";
}
```

### Display Messages

```javascript
function showMessage(type, message) {
  // type: "success", "error", "info", "warning"
  const alertDiv = document.createElement("div");
  alertDiv.className = `alert alert-${
    type === "error" ? "danger" : type
  } alert-dismissible fade show`;
  alertDiv.innerHTML = `${message}<button class="btn-close" data-bs-dismiss="alert"></button>`;
  document.getElementById("messageContainer").appendChild(alertDiv);
}
```

### Success/Failure Redirect

```javascript
if (result.success) {
  window.location.href = "/success.html?txnId=" + result.transactionId;
} else {
  showMessage("error", result.message || "Payment failed");
}
```

## NMI Integration Details

### Collect.js (NMI Direct Post)

- **Use when:** Simple card tokenization needed, no 3DS required
- **Files:** `Main.html`, `main.js`
- **Key Variables:** `DEFAULT_KEYS` (sandbox/secure), `COLLECT_STATIC_DATA_ATTRIBUTES`
- **Flow:** Collect.js → token → `PaymentController` → NMI transact.php

### Payment Component (3DS 2.0)

- **Use when:** 3DS authentication required, modern payment methods needed
- **Files:** `PaymentComponent/paymentComponent.html`, `PaymentComponent.js`
- **Packages:** `@nmipayments/nmi-pay`
- **Flow:** Form → NMI widget → 3DS challenge (if required) → backend

### Cloud POS (Customer-Present)

- **Use when:** In-person payments on POS devices
- **Files:** `CloudApi/cloudPOS.html`, `cloudPOS.js`
- **Authentication:** Bearer token in Authorization header
- **Unique Features:** Device list, async/sync transactions, POI prompts (tip, signature, menu)

## Common Tasks

### Add New Form Field

1. Add HTML input to form with `name="field_name"`
2. Update `getFormData()` if special handling needed
3. Pass in `paymentRequest` object to backend

### Handle API Errors

```javascript
if (!response.ok) {
  const errorText = await response.text();
  // Try JSON first
  try {
    const errorJson = JSON.parse(errorText);
    console.error("Error details:", errorJson);
  } catch {
    console.error("Error response:", errorText);
  }
}
```

### Debug Payment Flow

1. Open DevTools (F12)
2. Check Console tab for logged payment data
3. Check Network tab for API calls to `/api/yourendpoint`
4. Inspect form data with `getFormData()`

## Performance Tips

- **Lazy load payment widgets:** Only load NMI scripts when needed
- **Cache form data:** Store user preferences in localStorage for subsequent visits
- **Minimize DOM reflows:** Batch DOM updates

---

## Accessibility

- All inputs: Use `<label>` or aria-label
- Buttons: Use semantic `<button>` with descriptive text
- Color: Don't rely on color alone for error states (use icons + text)
- Focus: Ensure keyboard navigation works end-to-end
